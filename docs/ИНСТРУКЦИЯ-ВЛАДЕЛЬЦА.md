# 📚 ИНСТРУКЦИЯ ВЛАДЕЛЬЦА — Электрик Чолпон-Ата

## 1. Как работает сайт
Это **статический сайт** (Astro). Нет CMS, нет базы данных на сервере. Весь контент собирается из JSON (`data/*.json`) в HTML при деплое. Правите данные — сайт пересобирается.

---

## 2. Как менять цены и услуги
```bash
# Правите файлы в data/services/*.json (85 услуг в 10 категориях)
# Пример: цена на замену розетки
vim data/services/rozetki-vyklyuchateli.json   # найти "slug":"zamena-rozetki"
# Меняете price_min / price_max
# Пересборка:
npm run build
# Деплой (через 2 мин на сайте):
npm run deploy
```

---

## 3. Как менять контакты (в ОДНОМ месте!)
```bash
vim data/site.json
# Меняете: phone_display, phone_raw, whatsapp, telegram, email (refertur@yandex.ru)
# Пересборка: npm run build
```
После этого **все 384 страницы** получат новые контакты в футере, в префиллах WhatsApp и в CTA-блоках.

---

## 4. Как добавлять новых мастеров
```bash
vim data/masters.json
# Меняете status: "todo" → "active"
# Указываете specialties (slugs услуг) и areas (slugs сёл)
# После сборки карточка появится на /mastera/
```
В данный момент **все мастера — заглушки** (TO DO). После заполнения: `npm run build && npm run deploy`

---

## 5. Как добавить село в географию
```bash
vim data/locations.json
# Добавляете объект с ОБЯЗАТЕЛЬНЫМ полем "pre" (склонение в русском):
# {"slug":"myselo","name":"Моё Село","pre":"Моём Селе","distance_km":30,...}
# Для 7 приоритетных услуг автоматически генерируются гео-страницы (7 новых URL)
# Пересборка: npm run gen && npm run build
```

---

## 6. Как редактировать блог
- **Вручную**: создать `content/blog/МОЯ_ТЕМА.md` с frontmatter (title, description, h1, lead, type: blog, slug, date, keyword, faq, citations)
- **Автоматически**: добавить тему в `data/blog-plan.json` со статусом `todo`, затем:
```bash
npm run fetch-blog    # скачивает источники в docs/research/fetched/
# Рерайт черновика под правила конституции (ответ ≤100 симв., ≥3000 зн., таблица, FAQ)
npm run gen            # генерирует .md + llms.txt
npm run build
```

---

## 7. Калькулятор сметы (`/kalkulyator/`)
Страница работает **без сервера** (vanilla JS). Данные загружаются из `public/` через встроенный JSON. Для изменения цен: меняете `data/services/*.json`, запускаете `npm run gen` — калькулятор автоматически обновляет диапазоны и текст префилла.

## 9. Как поменять дизайн / тему
- **Цвета**: CSS-переменные в `src/layouts/Base.astro` секция `<style>` (строка 8)
- **Структура**: не меняется без перестройки Astro
- **Новые блоки**: добавляете `.astro` компонент в `src/components/` и подключаете в `Base.astro`

---

## 10. Как экспортировать данные для других сервисов
```bash
npm run db         # SQLite: services, locations, geo, tags, pages(375 строк), masters
npm run export     # CSV: services.csv, service_geo_pages.csv, locations.csv, tags.csv, bundle.json
```
`bundle.json` = полный JSON всех сущностей — готов для API или загрузки в карты/CRM/маркетплейсы.

---

## 11. Что НЕ НАДО менять (важно!)
- `scripts/lib/types.ts` — типы сущностей (без них сборка падает)
- `scripts/lib/generator.ts` — чистые функции генератора (без `process.exit` — это библиотека)
- `data/services/*.json` — никогда не удаляйте поле `name_gen` (склонение) и `geo_priority` (без него гео не генерируются)
- `astro.config.mjs` — `SITE_URL` должно совпадать с `data/site.json.url`

## 12. Проверка перед деплоем (быстрый чеклист)
```bash
npm run validate   # должен показать: All checks passed ✓
npm run build      # должен показать: 384 page(s) built, Complete!
ls dist/index.html dist/uslugi/index.html  # страницы на месте
grep 'fcol' dist/index.html | wc -l        # футер 5 колонок
```
Если `validate` зелёный и `build` зелёный — можно деплоить: `npm run deploy` или `git push` с Actions.

---

## 13. Ошибка «No such file: data/services/*.json» при сборке
Это означает, что в папке `data/services/` появился файл без `.json` (например, `INDEX.md`). Убедитесь, что в `data/services/` только `.json` файлы. Скрипт `generate-content.mjs` фильтрует `.json` (исправлено в v1.2), но проверьте, что `data/services/INDEX.md` отсутствует или удалён.
